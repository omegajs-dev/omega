# @omega.js/devkit

Shared build-time internals for the OMEGA frameworks. **Private workspace package — never published to npm.** (The vendorable-private set is devkit, config, account, template-kit, analytics, monitoring — `VENDORABLE_PACKAGES` in [tools/vendor.js](../../packages/devkit/tools/vendor.js) is the SSOT.)

## How frameworks consume it

Frameworks require modules by name (`require('@omega.js/devkit/logger')`) and declare `@omega.js/devkit` as a **devDependency** (workspace-linked in the monorepo, absent from consumer installs). At prepare time, each framework's `preparePackage.hooks.after` runs [tools/vendor.js](../../packages/devkit/tools/vendor.js) (with `afterBlocking: true`, so a vendor failure aborts the prepare instead of warning past it; it runs SECOND, behind `prepare-guard.rewire()`, and an aborted prepare still ends with the #350 gate wired, [#870](https://github.com/Omega-JS-Stack/omega/issues/870)), which copies the referenced modules into the framework's `dist/vendor/devkit/` and rewrites the requires to relative paths, so published tarballs are self-contained with zero **private** `@omega.js` references (enforced by CI's pack-smoke). Published `@omega.js` RUNTIME deps (desktop/extension's `@omega.js/client`) are never vendored: they stay normal package requires and resolve from the consumer install.

The closure covers the VENDORED trees too ([#739](https://github.com/Omega-JS-Stack/omega/issues/739)): a vendored module's own cross-package requires are rewritten to the sibling vendored copy (`dist/vendor/devkit/license.js` requires `../config/index.js` and `../account/index.js`), and any vendorable that only a vendored file needs is vendored beside it even when the host references it nowhere. Before that the copies shipped those specifiers verbatim, which resolved through the workspace symlinks in the monorepo and threw MODULE_NOT_FOUND on a published install, the private packages never being there. A published runtime dep stays a package require inside the vendored trees as well.

Vendored code resolves its deps (chalk, node-powertools) from the HOST framework's dependencies — the vendor tool fails if the host doesn't declare them.

## Boot preludes ([#890](https://github.com/Omega-JS-Stack/omega/issues/890))

Every framework CLI boot runs two steps before the verb, in this order: the freshness guard (`freshnessBoot`, [local-dev.md](../shared/local-dev.md)), then the boot PRELUDES. All five entries (web, backend, desktop, extension, manager) carry the identical call, which is the parity the list depends on:

```js
require('@omega.js/devkit/preludes').runPreludes({ verb: process.argv[2], targetDir: process.cwd() });
```

A verb whose row in the verb table is `readOnly` (today the manager's `status`) skips both boot steps: `freshnessBoot` and `runPreludes` read the flag off the table themselves (`isReadOnlyVerb`, on the first argument as typed), because a heal or a prelude may write (a dist, an origin heal, a docs sync) or print a note, and that verb leaves every file as it was and owns its output. No entry passes anything new.

The freshness guard was the ONLY seam above every verb, so anything else the whole CLI surface has to settle first had nowhere to live and lived nowhere: a brand clone left pointing at a redirected GitHub repo was checked by no verb at all.

**A prelude is one file exporting `{ name, verbs, run }`**, with one concern. `verbs` is `'all'`, one verb name, or a list of them, and the runner runs the MATCHES in list order. The filter reads the verb as TYPED (the first positional, before any framework's alias table resolves it, since the tables are the frameworks' and this runs above them), so a flag where the verb goes (`-v`) and a bare `omega` are both "no verb": only an `'all'` prelude covers them. A prelude declaring no usable `verbs` fails loudly at the filter, naming itself, before anything has run.

**A prelude is CHEAP and NON-INTERACTIVE**: local reads, at most one network call, never a prompt. Anything heavier is a manage op in its own service, where a walk reports it and a dry run plans it. Nothing is cached per process: a dispatcher hop that re-enters a `run()` runs the preludes again, and every prelude being idempotent, the second pass is a local read that finds its work already done.

**A prelude that STOPS the run throws with one line of why**, which the runner prints (prefixed `omega:`, no stack) before exiting 1: the same presentation the freshness guard's loud stops use, so a refused boot reads the same whichever step refused it. Everything a prelude expects to find in the world (no brand, no `.git`, no network) is a silent no-op instead, because a boot step that narrates the ordinary would print on every verb forever.

**Every line a prelude prints goes to stderr**, its notes (`origin healed from <old> to <new>`, the drift line, the docs sync line) and the runner's stop line alike. A prelude runs before the verb, and a verb's stdout may be machine-readable: `omega test --reporter=json` promises one JSON document there.

| Prelude | Verbs | What it does |
|---|---|---|
| `origin-heal` | `all` | Asks GitHub about the repo the checkout's `origin` already names (`gh api repos/<owner>/<name>`, which follows GitHub's own 301 after a transfer or a rename) and points the remote at the `full_name` that answer carries, printing `origin healed from <old> to <new>`. The REDIRECT is the authority, not the config: a brand is healed onto wherever its repo actually moved, config or no config, at the price of one GitHub read per boot (bounded at ten seconds, so a stuck network lands on the same silent unreachable case as an offline one). A transfer leaves every clone on the old address and git follows the redirect silently, so nothing ever complained until a push landed somewhere the brand no longer is (the `omega-omega` transfer into `Omega-JS-Stack`, 2026-09-12). Then DRIFT, on whatever that answer was: the WHOLE slug against the source repo the config derives (`@omega.js/config`'s `repoDrift`, case-insensitive, so a rename drifts as surely as a transfer, [#934](https://github.com/Omega-JS-Stack/omega/issues/934)) prints `origin is <slug> but config derives <derived>: fix repo.owner in config/omega.json5 or move the repo` and nothing more, because a fatal boot would lock out the verbs that fix it and this prelude never writes config. The verbs that ACT on the derived repo (the manage walk's repo service, the deploy lane) refuse on the same line instead. Every other case is a silent no-op: no brand root, no `.git` AT the brand root (never a walk up, so a brand nested in another repo cannot have the enclosing remote rewritten), no `origin`, a non-GitHub remote, a slug GitHub answers as itself (converged), a repo GitHub 404s (it is gone), or a GitHub it cannot reach. The WRITE is the one loud failure: a `set-url` refused after a `get-url` just answered is a broken invariant, not an external condition |
| `docs-sync` | `all` | When the brand's `@omega.js/manager` resolves to a monorepo checkout, syncs that manager's `docs/` from the monorepo's `docs/` through the checkout's own docs lane (`tools/vendor-docs.js` `syncDocs`), writing only changed files and printing one line when it wrote any. A published manager and a run outside a brand are left alone ([agent-docs.md](../shared/agent-docs.md)). |

### The case runner

One runner for every `defineCases` suite, on `node:test` in ONE process by default (`run()` with `isolation: 'none'`, no child per file; `isolation: 'process'` gives each file its own child), with one layer registry and one reporter. The library packages (`account`, `analytics`, `client`, `config`, `devkit`, `manager`, `mcp-router`, `monitoring`, `template-kit`) and the root `scripts/*.test.js` run on it through `./test/cli`: a library's `npm test` is `node ../devkit/src/test/cli.js` (devkit's own is `node src/test/cli.js`), with `--isolation=process` for `client`, `config`, `devkit` and `manager`, and the root `test:packages` runs `node packages/devkit/src/test/cli.js --root=scripts --log=.temp/logs/scripts.log`. Backend runs on it too, through its `omega test` (framework `backend`, with its `emulator` layer driver), and so does web, through its `omega test` (framework `web`, `isolation: 'process'` with the runner's default `concurrency`, `serial: ['watch']`, [web/test-framework.md](../web/test-framework.md#how-the-files-run)), and so do desktop and extension, through theirs: each verb builds `createRunner` with one driver per `app` row (desktop `main`, `renderer`, `boot`; extension `background`, `view`, `boot`).

| Export | What it is |
|--------|-----------|
| `./test/runner` | `createRunner(config)` → `{ run(options) }`. `config` is `{ framework, title, projectRoot, roots: [{ source, dir, cwd }], packageName, frameworkAliases, drivers, init: { factoryArgs, setupContext }, log, lanes, extendedModeLines, defaultTimeout, isolation, concurrency, serial }`, `framework` being a `./test/layers` key; `packageName` is the package whose own suites make a run a framework self-test (a `framework` root is among `roots` and the `package.json` at `projectRoot` carries that name: a bare run then means the framework suite, and a framework root's `boot/` suites, skipped otherwise, run); `frameworkAliases` are the scope prefixes a target may name the framework source with, beside the universal `framework:`, `omega:` and `mgr:` (backend passes `['backend']`); `extendedModeLines` are the detail lines printed under the shared extended-mode headline when the run is extended (default one generic line); `run({ targets, filter, layer, lane, extended, reporter })` resolves to `{ passed, failed, skipped, noMatch, durationMs, tests }`. Each file's case events and its child's output are held while it runs and released whole, in discovery order, so the pretty output, the json report's `tests` order and the log read as a `concurrency: 1` run reads; only durations differ. ## Rules

- `src/` holds ONLY vendorable runtime modules — anything in `src/` ships inside every framework's dist. Build-side tooling goes in `tools/`.
- Tests: `npm test` is `node src/test/cli.js --isolation=process`: one case-runner pass over all of `test/`, each file in its own child.
